# Pack 5: Report as a record plus instance email

!!! info "Research notes, not workbook guidance"
    **Status:** Open · **Last checked:** 2026-11-12 · Steps are drafts until a sandbox run confirms them.

**Question:** can the daily report be kept as a ServiceNow record, with the report attached,
and mailed by the instance's own email? What retention and access rules apply to it?

**Why it matters:** instance email avoids giving any app Graph `Mail.Send`, and a record gives
the report the instance's history and access controls. Both need checking.

## You need

- The `admin` role in the sandbox.
- A test mailbox `<test-mailbox>` that can receive mail from the instance.
- Optional: the probe from pack 2, to put real on-premises read output into the report.

## Steps

### 1. Check that the sandbox can send mail

Go to **System Properties > Email Properties** and record:

- whether **Email sending enabled** is on;
- any test or redirect address. Sandboxes often send all mail to one test address
  (property `glide.email.test.user`).

Change neither on a shared sandbox without its owner's agreement.

### 2. Create a table for the reports

1. Go to **System Definition > Tables**, select **New**.
2. Label `FMW Daily Report`; name `u_fmw_daily_report`. Leave **Extends table** empty.
3. Add two columns: `Report date` (Date) and `Summary` (String, length 4000).
4. Save.

### 3. Create a report record, attach the report and send the email

Go to **System Definition > Scripts - Background**, paste this, replace the placeholder, and
select **Run script**.

```javascript
var today = new GlideDate();
var body = 'FMW sandbox daily report\n' +
  'Generated: ' + new GlideDateTime().getDisplayValue() + '\n' +
  'Lines: example only';

var rpt = new GlideRecord('u_fmw_daily_report');
rpt.initialize();
rpt.setValue('u_report_date', today.getValue());
rpt.setValue('u_summary', 'Example report generated by pack 5');
var rptId = rpt.insert();

new GlideSysAttachment().write(rpt, 'daily-report.txt', 'text/plain', body);

var mail = new GlideRecord('sys_email');
mail.initialize();
mail.setValue('type', 'send-ready');
mail.setValue('recipients', '<test-mailbox>');
mail.setValue('subject', 'FMW sandbox daily report ' + today.getDisplayValue());
mail.setValue('body', body.replace(/\n/g, '<br>'));
mail.setValue('content_type', 'text/html');
mail.setValue('target_table', 'u_fmw_daily_report');
mail.setValue('instance', rptId);
gs.info('Report ' + rptId + ' email ' + mail.insert());
```

If your release ignores direct `sys_email` inserts, use a flow instead: trigger **Created** on
`u_fmw_daily_report`, then the core **Send Email** action, which needs no IntegrationHub
licence. Record which method worked.

### 4. Check the record and the mail

- Open **u_fmw_daily_report.list** and the new record. Confirm the attachment is there.
- Open **System Mailboxes > Outbound > Sent**. Confirm the mail is listed and linked to the
  record.
- Confirm `<test-mailbox>` received it (or the redirect address, if one is set).

### 5. Check retention

1. Go to **System Definition > Auto Flush** (table `sys_auto_flush`). Record any rule for
   `sys_email` and for `u_fmw_daily_report`. A new table normally has none, so its records
   are kept until someone deletes them.
2. Record any archive rules: **System Archiving > Archive Rules**.

### 6. Check access

1. Go to **System Security > Access Control (ACL)** and filter **Name** starts with
   `u_fmw_daily_report`. Record the ACLs the table was created with.
2. Use **Impersonate User** to open the record as a user with no roles. Record whether they can
   see it.

### 7. Optional: put real data in the report

Replace the `body` line in step 3 with the payload from pack 2's ECC queue input, to show the
on-premises read and the report joined up.

### 8. Clean up

Delete the test records, or the table if the sandbox owner prefers.

## Pass criteria

| Check | Pass |
|---|---|
| Record created with the attachment | Yes |
| Mail sent by the instance | Listed in Sent, received by the test mailbox |
| Retention for reports and mail | Recorded |
| Access for a user with no roles | Recorded; reports not readable by default |
